支付异常回路

展示支付授权失败、补单重试、人工介入和状态回补之间的异常处理闭环。

index.md diagram.mmd diagram.svg

业务背景

在高峰时段，支付通道抖动和状态回调延迟很常见。业务侧既要保证用户侧感知清晰，也要保证订单状态、支付状态和账务状态最终一致。

处理闭环

  • 交易起点完成锁单和支付授权发起，确保异常发生前订单处于可恢复状态
  • 异常决策阶段根据授权结果区分成功、失败重试、补单核对和人工介入
  • 状态回补阶段负责订单确认、消息通知和账务落账，保证用户状态和资金状态最终一致

关键边界

  • 重试应限定阈值，超过阈值后必须切入补单或人工处理，避免无界重放
  • 通知回补和账务落账不能依赖单一回调结果，需要有独立的补偿入口
