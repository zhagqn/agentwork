# /android [android-device-id] <android-task-desc>

Android 自动化工作流命令（手动触发）。

> 定位：跨项目通用能力入口。默认用“口语化任务描述”驱动执行，不要求用户记复杂子命令。

## 第一性原则（必须遵守）

1. 能力优先于工具：先定义“连接、准备、执行、取证、恢复”能力，再绑定实现。
2. 可复现优先：每次任务都能复放（设备、输入、产物路径明确）。
3. 取证优先：失败先保留日志/截图/UI dump，再下结论。
4. 安全默认值：默认低风险动作；高风险动作必须确认。

## 前置检查（按需启用）

- 模板默认不预置 Android MCP。
- 若执行时 server 不存在/不可用，先执行 `/android init` 完成项目级配置，再继续 `/android ...`。
- 设备类型不限（手机/平板/TV/机顶盒/模拟器），命令语义保持一致。

## 子命令（精简）

| 子命令                            | 作用                                                 | 示例                                                         |
| --------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| `init`                            | 初始化 Android 工作流能力（一次性配置）             | `/android init`                                              |
| （默认）`[android-device-id] <android-task-desc>` | 用口语化描述直接安排具体测试事项（推荐日常使用） | `/android emulator-5554 验证登录流程，失败时抓日志和截图`   |

## /android init 是做什么的？

`/android init` 的目标是“把环境准备好”，不是“执行业务测试”。

### 主要作用

1. 检查依赖是否齐全（`adb`、可选 UI 轨运行时等）
2. 确认设备接入方式（USB/Wi-Fi/模拟器）与默认 `<android-device-id>`
3. 确认能力实现（System 轨、UI 轨，可替换）
4. 写入项目级配置（优先 `.codex/config.toml`、`.mcp.json`）
5. 做一次最小验收（连通性 + 最小动作）

### 通过标准

- `adb` 能识别设备
- 至少一条轨道可完成最小动作（建议双轨都可用）
- 回退脚本可用：`.shared/scripts/android-shell-pull-fallback.sh`

## /android [android-device-id] <android-task-desc>

用自然语言描述你想做的事，助手负责拆解并执行。

### 输入规则

- `<android-device-id>` 可选；省略时默认使用：
  - `ANDROID_DEVICE_ID` 环境变量，或
  - `adb devices` 的首个在线设备
- `<android-task-desc>` 必填，建议包含：
  - 目标（要验证什么）
  - 范围（哪个页面/流程）
  - 约束（轮次、超时、是否需要证据）

### 推荐表达（口语化）

- `/android 验证当前设备的登录流程，连续跑 5 次，失败要截图和日志`
- `/android emulator-5554 从启动到首页走一遍，帮我判断是否稳定`
- `/android 192.168.31.201:5555 做回归冒烟，重点看返回键和焦点是否异常`

### 助手默认执行流程

1. 先做最小连通性检查
2. 按任务描述拆解步骤并串行执行
3. 自动采集关键证据（日志/截图/UI dump），默认写入项目根 `.tmp/android-test/`
4. 出现 `exec-out ... error: closed` 时自动切换 `shell + pull` 回退链路
5. 输出可复核结论（通过率、失败点、证据路径、下一步建议）

### 输出要求

- 给出任务理解摘要（1-3 行）
- 给出执行结果与关键证据路径
- 给出风险与下一步（如需）

## 推荐通用实践

- 日常使用默认命令，不强依赖子命令记忆负担。
- “先描述目标，再描述约束”，减少歧义。
- 先小范围冒烟，再扩展到回归批次。
- 对老设备保留回退链路，避免把兼容问题误判为业务失败。
- 临时产物默认写入项目根 `.tmp/`，Android 任务建议固定在 `.tmp/android-test/`。
- 占位符命名统一参考：`.shared/constraints/placeholder-naming.md`
