# /figma [subcommand] [args]

Figma 设计读取与分析命令（手动触发）。

> 定位：在实现前先理解设计意图与约束，默认输出“设计思路与实现建议”，而不是直接把设计写成代码。

## 默认连接策略（本地优先）

- 默认按 **Desktop MCP（本地）** 执行，优先使用“当前选区”（selection-based）。
- 仅在以下情况才切换 link-based：
  - 用户明确提供了节点链接；
  - 当前无选区且用户希望读取远端节点。
- 不主动要求用户提供 URL；本地工作流优先“选中元素 → 读取分析”。

## 前置检查（按需启用）

- 模板默认不预置 `figma` MCP（避免给不需要设计能力的项目增加系统配置）。
- 若执行时提示 `figma` server 不存在/不可用，先通过 `figma` skill 补齐项目级 MCP 配置，再继续 `/figma ...`。
- 优先写入项目级配置文件（`.codex/config.toml`、`.mcp.json`），不要默认写全局配置。

## 触发约束（必须遵守）

- 仅在用户**显式输入** `/figma ...` 时执行；禁止自动触发。
- 默认不输出完整页面代码（如 React/Vue/Tailwind 成品）。
- 样式分析以“视觉策略 + 约束 + 风险”为主，不假设设计稿已具备可复用命名或组件化结构。
- 设计样式出现小数时，默认按就近值取整并标注为近似值；仅在用户明确要求或小数会影响关键效果时保留小数精度。
- 若用户明确要求生成代码，可在 `/figma brief` 结果基础上再进入实现阶段。
- 若需要落盘截图、节点上下文或简报文件，默认写入 `[figma-artifact-root]`（建议 `.tmp/figma`）。

## 子命令

| 子命令                  | 作用                           | 示例            |
| ----------------------- | ------------------------------ | --------------- |
| （无）                  | 快速读取当前选区并输出设计摘要 | `/figma`        |
| `init`                  | 交互式初始化 Figma MCP         | `/figma init`   |
| `focus`                 | 查看当前选区（当前焦点）       | `/figma focus`  |
| `read [figma-target]`   | 读取指定节点的上下文与截图     | `/figma read`   |
| `brief [figma-target]`  | 生成“实现简报”（非代码）       | `/figma brief`  |
| `review [figma-target]` | 审查设计一致性与可实现性风险   | `/figma review` |

## /figma init

用于在“默认未接入”场景下，交互式完成 Figma MCP 配置。

### 交互流程（必须按顺序）

1. **确认接入目标**：
   - 当前助手配置文件路径（`.codex/config.toml` / `.mcp.json`）；
   - 是否已有 `figma` server（有则确认是否覆盖）。
2. **确认 MCP URL**：
   - 默认 `http://127.0.0.1:3845/mcp`；
   - 若用户本机端口/代理不同，改为实际 URL。
3. **本地可用性核验**（关键）：
   - 运行 `.shared/scripts/figma-mcp-health-check.sh <mcp-url>`；
   - 若失败，先输出排查建议（是否启动 Figma Desktop MCP、端口是否监听），并让用户决定“先修复再写配置”还是“先写配置稍后验证”。
4. **写入 MCP 配置**（项目级优先）：
   - 按当前助手格式写入 `figma` server；
   - 不默认写全局配置。
5. **完成验证**：
   - 提示用户重启/reload 助手；
   - 用 `/figma focus` 做功能验收。

### 通过标准

- `figma` server 已写入项目级配置；
- 健康检查可连通（或用户已确认稍后修复）；
- `/figma focus` 可正常返回选区信息。

## /figma（无参数）

对当前选区做一次“可落地摘要”，用于快速同步上下文。

### 执行流程

1. 调用 `get_metadata` 获取选区节点列表
2. 若为单节点：调用 `get_design_context` + `get_screenshot`
3. 若为多节点：按节点逐个调用 `get_design_context` + `get_screenshot`
4. 可选调用 `get_variable_defs`（如需要变量/样式来源）
5. 若用户要求保存截图/上下文，默认落盘到 `[figma-artifact-root]` 对应子目录
6. 输出摘要（非代码）：
   - 设计目标（该区域在页面中的作用）
   - 信息层级（主次关系）
   - 视觉策略（字体、色彩、间距趋势）
   - 实施提醒（约束、风险、待确认项）

## /figma focus

查看“当前焦点元素”并确认定位是否正确。

### 输出要求

- 至少包含：`nodeId`、名称、类型、位置尺寸
- 多选时按列表输出，禁止默认合并为单节点结论
- 无选区时明确提示：请先在 Figma 中选中元素（本地优先）；必要时再提供 node 链接

### 查看 node 值（nodeId）

- 首选：执行 `/figma focus`，从输出中的 `nodeId` 直接读取（如 `1:28`）。
- 备选：在 Figma 中对目标图层使用 “Copy link to selection”，链接中的 `node-id` 即 node 值（通常是 `1-28`，换成 `1:28` 即可用于 MCP）。

## /figma read [figma-target]

读取一个具体节点（或链接）的完整上下文，作为后续分析输入。

### 参数

- `figma-target` 可为：
  - `nodeId`（如 `1:28`）
  - Figma 链接（包含 `node-id`）
- 省略参数时：
  - 默认使用当前选区（Desktop MCP）
  - 若无选区：提示先选中元素；仅在用户明确需要 link-based 时再要求提供链接

### 执行规则

1. 先 `get_design_context`
2. 必须补 `get_screenshot` 做视觉对照
3. 需要样式来源时再调 `get_variable_defs`
4. 若节点过大或返回稀疏信息：先 `get_metadata` 拆分子节点，再按子节点读取
5. 若需保存截图或节点 JSON，默认写入 `[figma-artifact-root]/screenshots/` 与 `[figma-artifact-root]/context/`

## /figma brief [figma-target]

产出“可实现但不绑定代码栈”的实现简报。

### 输出模板（建议固定）

1. **设计目标与场景**：该区域要解决什么问题
2. **结构拆分建议**：建议拆成哪些模块（按职责，不按技术组件名）
3. **交互与状态**：默认/悬停/激活/禁用/异常等（若设计未体现，明确标注“待确认”）
4. **视觉策略**：主辅色、层级、节奏、留白、对齐规则
5. **实现建议**：优先级、依赖、风险、验收要点

### 约束

- 禁止直接给出整段页面代码
- 允许给“伪 token 建议”，但必须标明“建议值/待设计确认”

## /figma review [figma-target]

审查设计的一致性与落地风险，优先发现问题而非直接实现。

### 检查清单（精简）

- 信息层级是否清晰（标题、正文、辅助信息）
- 状态覆盖是否完整（交互、错误、空态）
- 视觉一致性是否稳定（字体/颜色/间距是否漂移）
- 可复用机会（可抽象区块）与不可复用原因（业务特例）
- 落地风险（文案溢出、多语言、极端尺寸、资源缺失）

### 输出格式

- 先列问题（按严重度）
- 再给修正建议（最小改动优先）
- 最后给“需设计师确认”的待办清单

---

## 通用最佳实践

- **先小后大**：先读目标局部节点，避免整页拉取导致上下文臃肿。
- **先结构后样式**：优先确认信息架构与交互，再讨论视觉细节。
- **截图必对照**：读取上下文后总是补截图，降低误读概率。
- **变量缺失可接受**：当 `get_variable_defs` 为空时，先记录现状，再提出规范化建议，不强行命名。
- **本地选区优先**：日常分析优先依赖当前选区，减少参数输入与定位成本。
- **链接用于复现**：跨会话协作或需要精确复盘时，再补充带 `node-id` 的链接。
- **临时产物收口**：截图、上下文、简报文件默认写入 `[figma-artifact-root]`。
- 占位符命名统一参考：`.shared/constraints/placeholder-naming.md`
