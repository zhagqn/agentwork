# /review [review-source]

对当前任务做一次 **双层 review**：
1. review 当前工件本身是否与事实对齐；
2. review 当前工作产物是否符合目标、计划与质量要求。

> `review-source` 指的是**要审查的工件引用**，通常是 Case 或 plan 文件路径，不是自然语言任务描述。

## 工作产物审查约束

- 审查实现是否保持最短有效调用链；删除无现存用途的过渡代码、纯转发封装、重复校验、重复抽象和无明确风险依据的防御分支。
- 具有明确安全、兼容性、事务或所有权边界依据的防御逻辑应保留，并在审查结论中说明理由。

## 输入来源
### 当前 Case
- 来源：当前 Case 或显式 Case ref
- 结果：更新 Case 的任务、结论、计划摘要、当前批次工作集、产出批次、风险 / 阻塞、审查记录
- 不默认写 `.tmp/agentwork/review/*.md`；只有用户明确要求导出 review note 时才额外写入

#### 当前 Case 必做流程
1. 读取当前 Case：优先看任务列表、已确认结论、计划摘要、当前批次工作集、产出批次、风险 / 阻塞、最近审查记录。
2. 取证当前事实：至少检查 `git status --short`，按当前批次工作集和用户问题读取相关 diff / 文件；需要时运行 `.shared/scripts/case-review.sh <case-ref>` 辅助发现过期路径和未覆盖改动。
3. 审查工作产物：先列真实问题，再列无问题结论；不要只审查 Case 文本，也要对照当前工作区事实。
4. 收敛 Case 快照：更新任务状态、已确认结论、计划摘要、当前批次工作集、产出批次、风险 / 阻塞。
5. 压缩历史记录：压缩重复路径、命令流水和重复验证，不按固定条数删除有独立语义的提交锚点、决策、约束、证据或风险。
   - `产出批次` 保留所有仍有独立行为、决策、验证或风险价值的提交；相关提交可以聚合到同一条，并用主题/目录范围代替逐文件清单。同一 hash 默认只出现一次，只有验证或边界明显不同才拆行。
   - 只有 Case 文件自身更新、格式/生成物同步或没有新增语义的连续提交，才合并为 `历史:` 阶段摘要；摘要保留时间范围和可追溯提交锚点（若存在）。
   - `审查记录` 先按标题中的实际审查日期识别新旧，再按时间倒序排列；不得把文档当前位置直接当作时间顺序。最近 3 个有独立结论或验证结果的审查事件（不足 3 个则全部）保留“变更 / 验证 / 风险/待办”的详细结论；`历史审查摘要`不计入这 3 个名额。更早事件按里程碑或时间段合并为一句话或简述，并保留日期范围、结论、验证状态、未闭环风险和可追溯锚点。
   - 更早记录若仍包含未解决风险、兼容/迁移前提、被否决方案或影响接力的旧结论，不受“简述”限制，必须保留足够上下文或明确指向可追溯来源；同一轮没有新增事实的重复审查可以合并。
   - 已关闭或仅作归档指针的 Case 可以主要保留历史摘要，不强行补造近期详情；前提是目标、最终结论、验证边界、未闭环风险和接续 Case / 提交锚点仍可追溯。
6. 完成前自检：确认 Case 仍是可恢复任务快照，并完成“信息保留检查”，而不是只得到结构通过。
7. 运行命令自检：在 `.shared/scripts/case-review.sh <case-ref>` 取证后，运行 `.shared/scripts/agentwork-check.py case <case-ref> --strict-flow` 校验 Case 形态。

若本轮 review 计划或用户要求使用 subagent 做局部复核，先参考 `.shared/patterns/subagent-workflow.md`，再拆分审查范围、指定输出格式和验收方式。

#### Case 收敛维护检查清单
- 任务列表：完成状态只写在 checkbox；仍未完成的后续项必须保留。
- 已确认结论 / 计划摘要：必须反映当前真实决策；删除或改写已失效方案、旧路径、旧入口和旧目标。
- 当前批次工作集：必须保留 `## 当前批次工作集（可选）` 小节；条目格式必须是 `- 范围: `path` | 主题: ...`。不要写成 `- 已完成:`、命令流水或审查结论。
- 当前批次工作集压缩：小批次可列精确路径；跨目录或超过约 20 个路径时改写为主题/目录范围，精确路径以 `git status`、`git diff`、`.shared/scripts/case-review.sh` 取证，不长期堆入 Case。工作集压缩不得替代产出批次中的提交锚点。
- 过期内容清理：移除已提交、已删除、已还原或不再属于当前批次的工作集路径；已解决风险不继续保留为当前风险。
- 空工作集：任务全部完成时可留空小节；还有后续任务但当前没有工作集时，在小节正文写 `当前无工作集。`。不为通过校验保留过期路径。重复提交锚点仅提示人工审查，独立验证或边界不同的记录可保留。
- 产出批次压缩：按提交/行为/决策归类，保留有独立语义的提交锚点；文件范围优先使用目录、模块或 glob，只有合同、入口、迁移、测试和关键配置才列精确文件。
- 审查记录压缩：先解析标题日期并按时间倒序整理，不按原文位置推断新旧；保留最近 3 个有独立结论/验证的审查事件，`历史审查摘要`不计入名额，更早事件合并为按里程碑/时间段的一句话或简述。旧 Case 或归档指针可直接保留历史摘要，但必须保留结论、验证状态、未闭环风险和来源锚点。不记录命令流水、重复验证过程、临时判断或已被 project 文档吸收的长期事实。
- 信息保留检查：压缩前逐项判断内容属于当前事实、关键决策/取舍、验证证据、兼容/迁移前提、风险/回滚边界、重复流水或已迁移内容。前五类必须保留在 Case 或明确指向另一个 Case、project、commit 或 review 工件；只有后两类可以删除或合并。
- 提交记录格式：`提交:` 后可列多个相关 hash；每条仍需有 `范围:` 和 `验证:`，范围按主题/目录归类，不要求罗列所有文件。
- 提交锚点可验证性：当前仓找不到的 hash 只能标记为“当前仓不可验证”，不得仅因 `case-review.sh` 无法校验就删除；需确认它是否来自旧分支、历史重写、独立仓或尚未同步的对象。
- 可恢复性：Case 顶部快照必须能让下一次 `/case load` 后恢复任务；保留目标、边界、关键入口、当前工作集、有效产出锚点、当前风险和后续项。
- Case 文件自身提交不为了回填自身 hash 再追加提交；该批次允许保留 `提交: -`，并依赖 Git 历史追踪真实提交。

#### 禁止的 Case Review 结果
- 只追加一条审查记录，但不更新任务、结论、计划摘要、工作集、产出批次和风险。
- 让旧目标、旧入口、旧目录或已废弃方案留在顶部工作快照。
- 把长篇历史命令流水、逐次 run 结果、临时分析和重复验证长期堆在审查记录中。
- 把 `agentwork-check.py case` 或其他结构检查通过当作语义收敛完成；结构通过只代表格式合格，不代表快照已压缩。

### Plan / Review 工件
- 来源优先级：
  1. 显式传入的 `review-source`
  2. 最新的 `.tmp/agentwork/plan/*.md`
- 结果：写入 `.tmp/agentwork/review/{YYYYMMDD-HHMM-slug}.md`
- 使用模板：`.shared/templates/review.md`
- 写入后运行 `.shared/scripts/agentwork-check.py review <review-note>`；若该 review 要作为“无阻塞问题”的完成 gate，再运行 `.shared/scripts/agentwork-check.py review <review-note> --fail-on-major`
