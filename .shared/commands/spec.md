# /spec [spec-source]

把已确认的设计整理成 **可执行、可验证、无占位** 的规格（spec）。

> 本仓库的 spec 同时承载“做什么 / 为什么”和“按什么任务切片做完”：编号决策说明要满足什么，任务行说明怎么分步交付与验证。它区别于社区工作流中只写需求、再单独拆 tickets 的 spec。
>
> `spec-source` 指的是**输入来源 / 引用对象**，通常是 brain note 或现有文本工件路径，不是自然语言任务描述。若要把 spec 写入 Case，使用 `/case spec [spec-source]`。

## 输出

- `/spec` 不创建或更新 `.shared/case/*.md`
- 来源优先级：
  1. 显式传入的 `spec-source`
  2. 最新的 `.tmp/agentwork/brain/*.md`

「最新」由 `.shared/scripts/agentwork-check.py latest brain` 判定，不按修改时间手选：只有符合 `YYYYMMDD-HHMM-slug.md` 的工件参与，最新时间戳存在多个候选时报 `ambiguous_latest` 并要求显式指定。完整规则见 `.shared/scripts/README.md`。

- 输出：`.tmp/agentwork/spec/{YYYYMMDD-HHMM-slug}.md`
- 使用模板：`.shared/templates/spec.md`
- `/spec` 只把已确认设计整理成规格，不代表可以开始修改源码；真正执行需明确的当前执行意图，例如 `/exec`、`/case exec` 或“按已确认 spec，现在开始修改”
- 需要写入 Case 时，后续显式调用 `/case spec [spec-source]`

## 必做流程

1. 复核输入来源：确认目标、边界、已选方案、非目标与约束；若只有“推荐方案（待确认）”或缺关键结论，回到 `/brain` 或先问用户。
2. 编号决策：把来源中已确认、会约束实现的结论写成 `D1..Dn`。每条只转写已确认结论，不在 `/spec` 中新增或弱化决策；发现缺失决策时回到 `/brain` 或先问用户。
3. 锁定范围与验证接缝：列出会影响的文件 / 模块 / 文档边界、明确不做的范围，以及本轮在哪一层验证（优先项目已有、最高层且稳定的验证入口）。
4. 拆成任务切片：每条任务是一个可独立执行、审查和验证的纵向切片，单个上下文可完成；大范围替换或改名按“先新增、再迁移引用、最后移除旧入口”拆分，避免中间状态不可用。移除任务显式依赖引用迁移与验证任务；每个停顿批次核对入口仍指向存在的文件，最终无残留不能替代中间批次可用性。
5. 写任务行：每条任务使用 `- [ ] T{n} {任务} | 覆盖: D{x}[, D{y}] | 依赖: T{m} | 完成: {可观察条件} | 验证: {最小验证}`。`覆盖` 与 `验证` 必填；`依赖` 只能写 `无` 或逐个列出的任务编号（如 `T1, T2`），无依赖时也可省略；`完成` 在验证本身即完成条件时可省略。每个决策至少被一个任务覆盖。决策行写成 `- D{n} ...`；任务行保持单行，`覆盖` 逐个列出编号，不写 `D1-D3` 这类范围。
6. 补完成标准与风险：复杂或多轮任务写清本轮完成标准、风险和阻塞条件。
7. 运行命令自检
   - 运行 `.shared/scripts/agentwork-check.py spec <spec-file>`；未显式路径时可用 `.shared/scripts/agentwork-check.py spec` 检查最新 spec
8. 给出下一步：spec 可执行后，下一步进入 `/exec`，或先用 `/case spec [spec-source]` 写入 Case 后再 `/case exec`；若 spec 仍依赖确认，停下来等确认。

## 关键要求

- 决策可追溯：每条任务标明覆盖的决策，每个决策至少被一个任务覆盖
- spec 检查在编写时生效；写入 Case 后，由 Case 自身保留的编号决策与完整任务行继续接受 strict-flow 检查
- D/T 编号唯一，依赖引用存在、不能依赖自身且不能形成环
- 任务是纵向切片，依赖显式写出
- 无占位符
- 先锁边界，再拆任务
- 每条任务都有最小验证

## 禁止事项

- 不在 `/spec` 阶段修改项目源码、README、脚本、配置、测试或业务文档
- 不重做完整方案对比；方案差异未收敛时回到 `/brain`
- 不在 spec 中新增来源未确认的决策
- 不把 spec 写成执行日志、命令流水或 audit 结论
- 不把模糊任务直接交给 `/exec`；边界、成功标准或非目标缺失时先澄清
- 创建或更新 `.shared/case/*.md`
