# Subagent Workflow

> 目的：定义使用 subagent 时的委派契约、输出格式和验收责任。本文是可选执行 pattern，不是 `/exec` 或 `/review` 的必做流程；触发读取规则见 `.shared/commands/exec.md`、`.shared/commands/review.md` 与 `.shared/patterns/session-workflow.md`。

## 基本边界

- Subagent 是执行过程中的可选协作机制，可用于并行调查、局部实现、重复比对或独立复核
- Subagent 不改变主 agent 的责任边界
- Subagent 输出是候选证据或候选改动，不自动等同于任务完成
- 最终整合、验证、提交判断和 session 更新由主 agent 完成

## 适用场景

- 多个独立文件、模块或概念需要并行比对
- 需要从不同角度复核同一批文档或代码
- 有清晰边界的局部实现任务
- 可用低成本模型完成的枚举、扫描、归纳或证据收集
- 主 agent 可以在等待期间推进其他非重叠工作

## 不适用场景

- 当前下一步被该结果直接阻塞，主 agent 应自己处理关键路径
- 任务边界模糊，无法判断完成标准
- 需要统一设计判断、最终架构决策或提交边界判断
- 多个 subagent 会同时修改同一文件或同一逻辑区域
- 只是为了“更彻底”而让多个 agent 重复扫描全局

## 委派契约

委派前应明确以下字段；无法明确时不应委派，或先由主 agent 收敛任务边界。

- 边界：检查或修改哪些路径、模块、概念；不处理哪些范围
- 目标：要回答的问题，或要交付的改动
- 判断标准：怎样算一致、完成、失败或需要上报
- 输出要求：需要返回哪些证据、结论、建议或改动清单
- 写入权限：是否允许改文件；若允许，限定写入范围
- 验收方式：主 agent 如何判断是否采纳结果

## 推荐输出格式

```text
结论：一致 / 不一致 / 不确定 / 已完成
证据：范围、文件 / 行号 / 小节或命令结果
问题：不一致、风险或缺口；没有则写“无”
建议 / 改动 / 验证：仅在有时列出
```

## 模型约定

- 调用时已指定模型的，以调用指令为准
- 未指定模型时，默认沿用主 agent 的模型与推理强度
- 只有任务的成本、速度或风险有明确差异时，才需要单独指定模型

## 主 Agent 责任

主 agent 必须约束输入、验收输出：

- 委派前：写清边界、目标、判断标准、写入权限和输出格式
- 返回后：核验证据，处理冲突或不确定项，决定是否采纳
- 采纳后：运行必要验证，只把高信号结论、范围和风险写入 session
