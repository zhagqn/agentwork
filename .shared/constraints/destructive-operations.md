# 破坏性操作安全约束

## 高风险操作清单

以下操作必须在执行前明确说明风险，并尽可能提供更安全的替代方案：

### 文件系统

- 删除文件或目录 (`rm -rf`, `del`)
- 覆盖重要文件

### 数据库

- 重建数据库
- 删除表或数据
- 数据迁移操作
- 持久化格式变更

### Git 操作

- `git reset --hard`
- `git push --force`
- `git rebase`（重写历史）
- 任何重写历史的命令

### Git index / staged 协作边界

Git index（staged 区）是用户组织提交批次和 review 边界的工作区状态，不是助手可以自动整理的临时缓存。

- 未经用户明确要求，不执行会改变 staged 区或暂存边界的命令，包括 `git add`、`git add -p`、`git restore --staged`、`git reset`、`git rm`、`git rm --cached`、`git mv`、`git update-index`、`git stash`、`git stash --staged`、`git commit` 等。
- 普通执行任务时只修改 working tree；不要为了“整理状态”主动 stage、unstage 或清空 staged 区。
- 如用户明确要求 stage / unstage / commit，先说明计划影响的路径和原因，再按用户确认的范围执行。
- 允许使用只读命令观察状态，例如 `git status`、`git diff`、`git diff --cached`、`git ls-files`。

### 其他

- 公共 API 变更
- 跨服务协议变更

## 处理策略

### 执行前必须

1. **明确说明风险**
2. **给出更安全的替代方案**（如先备份、先 `ls` / `git status`、使用交互式命令）
3. **确认用户是否确实要执行**

### Git/GitHub 特别规则

- **不要主动建议**使用重写历史的命令，除非用户明确提出
- 展示 GitHub 交互示例时，**优先使用 `gh` CLI**

### Rust 依赖查阅

- 优先给出基于本地 `~/.cargo/registry` 的命令或路径
- 使用 `rg` / `grep` 搜索
- 再考虑远程文档或源码

## 不需要确认的操作

以下操作可以直接执行，无需额外确认：

- 纯代码编辑
- 代码格式化
- 小范围结构重排
- 普通搜索
- 简单代码重构

### 自引入错误必须主动修复

本轮会话中引入的低级错误，直接修复，不需用户批准：

| 类型       | 示例                               |
| ---------- | ---------------------------------- |
| 语法错误   | 括号不配对、字符串未闭合、缺失分号 |
| 格式问题   | 破坏缩进或格式化                   |
| 编译期错误 | 缺失 `import`、错误的类型名称      |

修复后简要说明，视为当前改动的一部分。
