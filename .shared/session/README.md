# Session 目录说明

## 本项目补充说明

<!-- AGENTWORK:SESSION-README:START -->
> 目录用途：记录当前项目的 session 快照文件。
>
> - ✅ 写：当前任务的最小快照、任务列表、已确认结论、计划摘要、当前批次工作集、产出批次、风险 / 阻塞、审查记录
> - ❌ 不写：长期稳定项目事实（应摘录到 `.shared/project/*`）

## 使用约定
- 不自动加载旧 session
- 只在需要时显式 `/session load <session-ref>`
- 审查前优先运行 `.shared/scripts/session-review.sh`
- 当前批次工作集优先记录主题/目录范围；小批次可列精确路径，跨目录或超过约 20 个路径时不要把完整路径清单长期写进 session
- 精确改动路径以 `git status`、`git diff` 与 `.shared/scripts/session-review.sh` 为取证来源；session 只保留恢复任务所需的高信号范围
- 已提交结果按“产出批次（提交锚点）”记录，不再逐文件展开
- `/review` 时同步清理过期内容：已完成、已提交、已删除或不再属于当前批次的路径不继续留在“当前批次工作集”
- `/review` 时同步压缩历史产出：默认保留最近 3-5 条仍有追踪价值的产出明细，更早已闭环批次合并为阶段摘要或提交范围索引
- session 文件自身提交允许保留一条 `提交: -` 指向自身，不要求为回填它再额外做第三次提交
- session 不设置固定“当前阶段”字段；推进状态以任务列表、已确认结论、计划摘要、当前批次工作集、产出批次、风险与审查记录为准
- `/session load` 只恢复任务快照；需要精确实现或差异时，继续读取实际文件并按需使用 git 取证
- 临时思考过程不要直接沉淀为 session 结论
- 当任务列表无 open item、最近一次 `/review` 已覆盖当前工作产物、且无需继续接力时，session 可视为关闭；关闭后不再追加临时过程，只保留必要的产出锚点和阶段摘要
