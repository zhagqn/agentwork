## 已确认结论（工作快照）
### 目标
- CodeGraph 安装后各平台即可通过项目级 MCP 调用；Pi 与 Codex、OpenCode 共用技能入口；不再维护独立的 Pi MCP 扩展工具。
### 边界
- In Scope: `.agentwork/tools/codegraph/`、`install-tool.py` 的 MCP 所有权分支、pi-mcp 退役、相关测试、README、platform-adapter 与 project 文档，以及 figma、exa、octocode 的 Pi 接入参考。
- Out of Scope: figma、exa、octocode 的安装逻辑（保持用户手动接入）；下游项目迁移；`codegraph` CLI 安装与索引初始化。
### 约束
- 不暂存、不提交，除非用户显式要求。
- Pi 内置 MCP 视为默认能力，文档只列 `.pi/mcp.json`，不写 Pi 版本、扩展或退役迁移说明（用户 2026-10-03 确认）。
- 旧规则直接移除，不为已退役的 pi-mcp 提供自动迁移。
### 已选方案
- D1 codegraph 默认写入 `.mcp.json`、`.codex/config.toml`、`opencode.jsonc`、`.cursor/mcp.json`、`.pi/mcp.json`（`exposure: direct`），均启动 `codegraph serve --mcp`。
- D2 MCP 配置所有权：已有同名配置（含 OpenCode 的 `opencode.json`）保留并报告 `keep-existing`；内容与模板一致则纳入收据；安装后被改写的归项目所有，重装与卸载都保留。其他受管文件被改写仍报所有权冲突。
- D3 Pi 由原生 `.agents/skills/` 发现加载共用 codegraph 技能，旧 `.pi/skills/codegraph/` 按收据摘要退役。
- D4 移除 pi-mcp 可选工具；其他平台和工具的 MCP 接入说明不受影响。
- D5 figma、exa、octocode 仍为手动接入，参考文档补 Pi 段：`pi mcp add -l <name> --exposure direct ...` 写入项目 `.pi/mcp.json`；figma remote 额外用 `--oauth-client-name "Claude Code"` 并 `pi mcp login`（Pi 文档注明 Figma 只接受已知客户端注册）。exa、octocode 依赖 wrapper 自解析项目根，不需要 `cwd`。
### 关键决策 / 取舍（可选）
- 接受默认装 MCP 的代价：本机缺 `codegraph` CLI 时各客户端报 MCP 启动失败，`INSTALL.md` 已写明。项目无 `.codegraph/` 索引时 server 照常启动，调用返回 "No CodeGraph project is loaded"，不自动建索引（2026-10-03 实测）。
- figma、exa、octocode 不默认写配置：分别依赖桌面端运行、远程服务授权与 GitHub 认证，默认接线会造成启动失败或越权发送。
