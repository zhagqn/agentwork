# Case 目录说明

## 本项目补充说明

<!-- AGENTWORK:CASE-README:START -->
> 目录用途：记录当前项目的 Case 快照文件。
>
> - ✅ 写：当前任务的最小快照、任务列表、已确认结论、计划摘要、当前批次工作集、产出批次、风险 / 阻塞、审查记录
> - ❌ 不写：长期稳定项目事实（应摘录到 `.shared/project/*`）

## 使用约定
- 不自动加载旧 Case
- 只在需要时显式 `/case load <case-ref>`
- 审查前优先运行 `.shared/scripts/case-review.sh`
- 当前批次工作集优先记录主题/目录范围；小批次可列精确路径，跨目录或超过约 20 个路径时不要把完整路径清单长期写进 Case
- 精确改动路径以 `git status`、`git diff` 与 `.shared/scripts/case-review.sh` 为取证来源；Case 只保留恢复任务所需的高信号范围
- 已提交结果按“产出批次（提交锚点）”记录，不再逐文件展开
- `/review` 时同步清理过期内容：已完成、已提交、已删除或不再属于当前批次的路径不继续留在“当前批次工作集”
- `/review` 时同步压缩历史产出：保留所有仍有独立行为、决策、验证或风险价值的提交锚点；相关提交可合并为一条并按目录/主题归类，只有无新增语义的闭环批次才合并为带时间范围和来源锚点的阶段摘要
- `/review` 时分层压缩审查记录：先按标题中的实际日期识别新旧并按时间倒序整理，不按原文位置推断时间；保留最近 3 个有独立结论/验证的审查事件详情，历史审查摘要不计入名额；更早记录按里程碑或时间段保留一句话/简述，并带日期范围、结论、未闭环风险和来源锚点。已关闭或归档指针 Case 可主要保留历史摘要
- `/review` 时做信息保留检查：关键事实、方案取舍、验证证据、兼容/迁移前提和风险/回滚边界必须留在 Case 或明确指向其他可追溯工件；“高信号”不等于“只保留最近几条”
- 提交 hash 在当前仓不可见时只标记为不可验证，不自动删除；先判断旧分支、历史重写、独立仓或尚未同步对象等来源
- Case 文件自身提交允许保留一条 `提交: -` 指向自身，不要求为回填它再额外做第三次提交
- Case 不设置固定“当前阶段”字段；推进状态以任务列表、已确认结论、计划摘要、当前批次工作集、产出批次、风险与审查记录为准
- `/case load` 只恢复任务快照；需要精确实现或差异时，继续读取实际文件并按需使用 git 取证
- 临时思考过程不要直接沉淀为 Case 结论
- 当任务列表无 open item、最近一次 `/review` 已覆盖当前工作产物、且无需继续接力时，Case 可视为关闭；关闭后不再追加临时过程，只保留必要的产出锚点和阶段摘要
